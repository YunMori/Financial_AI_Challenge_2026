# K-Buddy API — 공통 의존성 (Python 3.12)

# planner 는 3.11 을 명시했으나, 로컬과 Docker 핀을 일치시켜 "로컬에선 됐는데
# 배포에서 안 되는" 사고를 제거한다. 휠 호환은 dev-log 2026-08-11 참조.
#
# ★ **이 파일을 직접 설치하지 않는다.** torch 와 onnxruntime 이 빠져 있다 —
#   둘은 장치에 따라 배포판이 갈려서 아래 둘 중 하나를 고른다:
#
#       pip install -r requirements.txt        # CPU — Docker · CI · 로컬 생성 미사용
#       pip install -r requirements-gpu.txt    # CUDA — 개발·판정 (ADR-005)
#
#   왜 나눴는가: `onnxruntime` 과 `onnxruntime-gpu` 는 같은 `onnxruntime` 모듈을
#   점유해 **공존할 수 없다.** 한 파일에 둘 다 넣는 방식이 성립하지 않는다.
#   torch 도 Windows 에서는 PyPI 휠이 CPU 전용이라 인덱스를 갈라야 한다.

# ⚠ **pip 이 문서의 가정보다 낮은 버전을 고른다** (실측 2026-08-19, pip 26.2).
#   과거 주석은 "충돌 경고가 뜨지만 실동작 정상"이라고 적었으나, 최신 resolver 는
#   경고 대신 **백트래킹으로 더 낮은 버전을 선택**한다:
#
#       chromadb  0.5.23 → 0.5.20   (0.5.23 의 `tokenizers<=0.20.3` vs transformers 5.15)
#       xgrammar  0.2.4  → 0.2.3    (0.2.4 의 `transformers<5`)
#
#   `pip check` 는 깨끗하다. 순수 파이썬 핀이라 Docker 도 같게 해소된다 —
#   환경이 깨진 게 아니라 **주석이 낡았던 것**이다. 단 Recall@5 93.9% 는
#   chromadb 0.5.23 기준 수치이므로 0.5.20 재확인이 필요하다.
