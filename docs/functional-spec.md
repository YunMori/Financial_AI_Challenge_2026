# K-Buddy 기능명세서

> **제출물.** 개발과 동시에 갱신한다 — 기능 하나를 구현할 때마다 해당 절을 채운다.
> 마지막에 몰아 쓰면 8주 차에 반드시 터진다(planner §1.2).

각 기능은 아래 8항목 고정 서식을 따른다. **미구현 기능도 헤더를 비워 두지 않고
남겨 둔다** — 빈 절이 보여야 남은 작업량이 눈에 들어온다.

```
1) 목적   2) 입력   3) 처리   4) 출력
5) 화면 연결   6) 예외 처리   7) 응답 계층   8) 검증 항목
```

**2)·4)의 소스는 Pydantic 스키마다** (`apps/api/app/schemas/`). 필드명·타입·필수여부는
스키마에서 옮겨 적고, 스키마에 나타나지 않는 것(검증규칙의 *이유*, 예외 판단 근거)만
손으로 쓴다. 스키마를 바꾸면 이 문서도 함께 바꾼다.

마지막 갱신: 2026-08-20 · 상태: **필수 F1~F5 전부 완료 / 확장 F6~F8 골격만**

| 기능 | 구분 | 상태 |
|---|---|---|
| F1 다국어 온보딩 | 필수 | ✅ S1·S2 구현 완료 |
| F2 계좌개설 내비게이터 | 필수 | ✅ 규칙만 (LLM 설명은 M1 제외) |
| F3 서류 체크리스트 PDF | 필수 | ✅ 조판 검증 통과 (컨테이너) |
| F4 한도제한계좌 해제 가이드 | 필수 | ✅ ChatPipeline 재사용 + F3 연결 |
| F5 근거 기반 QA 챗봇 | 필수 | ✅ 파이프라인 ①~⑩ 관통 · 로컬 CUDA 전량 채점 |

## F1. 다국어 온보딩 — 규칙 기반

### 1) 목적
이용자의 체류자격·거래목적을 파악해 이후 모든 안내를 개인화한다. 동시에
**수집 범위를 여기서 못 박아** 서비스 전체가 식별정보를 다루지 않도록 만든다.

### 2) 입력
소스: `app/schemas/chat.py :: SessionContext`

| 필드 | 타입 | 필수 | 검증규칙 |
|---|---|---|---|
| `nationality` | `str` (ISO 3166-1 alpha-2) | 아니오 | 정확히 2자, 대문자로 정규화 |
| `visa` | `VisaCode` (12종 열거) | 아니오 | 열거값 외 거절 |
| `stay` | `StayPeriod` (4구간) | 아니오 | 열거값 외 거절 |
| `purposes` | `list[Purpose]` | 아니오 | 최대 5개 |

**자유 입력 필드가 하나도 없다.** 전부 선택지다. 개인정보 최소 수집(§5.1)의
구현이자, 프롬프트 인젝션 표면을 온보딩 단계에서 0으로 만드는 설계다.

전 항목 선택 사항인 이유: 프로필 없이도 일반 안내는 가능해야 하고, 입력을
강제하면 첫 화면에서 이탈한다. 프로필이 비면 검색 메타데이터 필터만 해제된다.

**체류자격 12종 선정 근거** (2026-06, `corpus/stats/moj_24_…csv`):
12종 합계 1,973,900명 = 체류외국인의 68.7%. 빠진 상위는 B-2·C-3·B-1로
전부 단기체류라 계좌개설 대상이 아니다. 확장 후보는 F-3(동반, 84,976명).

### 3) 처리
규칙 기반. LLM 개입 없음.

### 4) 출력
`sessionStorage` 에 저장된 `SessionContext`. **서버로 전송되지만 저장되지 않는다.**
매 `/chat` 요청 body 에 실려 오며 서버는 요청 처리 후 폐기한다.

### 5) 화면 연결
S1 `/[locale]` (언어 선택) → S2 `/[locale]/profile` (`StepSelect` ×4, 진행률 바)

### 6) 예외 처리
| 상황 | 처리 |
|---|---|
| 입력 오류 | 열거값 외 → 422. 클라이언트가 해당 스텝으로 되돌림 |
| 검색 실패 | 해당 없음 |
| 외부 API 장애 | 해당 없음 |
| 계층 C | 해당 없음 |
| `localStorage` 오사용 | **금지.** 공용 PC 대비 — `sessionStorage` 만 사용 |

### 7) 응답 계층
해당 없음 (생성 없음).

### 8) 검증 항목
✅ 골든셋 문항 없음 — 규칙 기반이라 단위 테스트로 대체했다.
`apps/api/tests/test_schemas.py :: TestSessionContext` **5케이스** —
전 항목 선택 · 국적 대문자 정규화 · alpha-2 외 거절 · 열거값 외 체류자격 거절 ·
체류자격 표기가 하이픈 형식(`E-9`)인지. 마지막 항목이 검색 토크나이저의
`E-9`/`E-7` 변별과 맞물린다.

## F2. 계좌 개설 내비게이터 — 규칙만 (LLM 없음)

### 1) 목적
체류자격을 기준으로 **어느 은행에서 무엇이 확인됐는지**를 보여준다. 이 기능의
값어치는 "가장 좋은 은행"을 고르는 데 있지 않고 **확인된 것과 확인하지 못한
것을 갈라 보여주는 데** 있다 — 96셀을 공식 문서로 다 채우는 것은 불가능하고,
억지로 채우면 그 자체가 환각이 되기 때문이다(planner §4.2).

### 2) 입력
소스: `app/schemas/institution.py` · 쿼리 파라미터

| 필드 | 타입 | 필수 | 검증규칙 |
|---|---|---|---|
| `lang` | `Lang` (ko/en/vi) | 아니오 (기본 ko) | 열거값 외 422 |
| `visa` | `VisaCode` (12종) | **아니오** | 열거값 외 422 |

`visa` 가 선택인 이유: 프로필 없이도 기관 단위 정보(모바일 외국인등록증 수용
여부)는 성립한다. F1 이 "프로필이 비면 필터만 해제된다"고 한 것과 같은 규칙이다.

### 3) 처리
**전부 규칙이다. LLM 호출이 없다.**

| 단계 | 구현 |
|---|---|
| 매트릭스 로드 | `app/matrix/loader.py` — 프로세스당 1회 캐시 |
| 불변식 검증 | 같은 파일. **근거 없는 `official` 은 로드 시점에 `ValueError`** |
| 점수 산출 | `app/matrix/fit.py` — 순수 함수 |
| 응답 조립 | `app/matrix/service.py` |

**기관 목록은 `common.mobile_arc` 에서 승격했다.** 보도자료
`FSC-2025-0321-MOBILE-ARC` 가 6개 은행을 이름으로 열거하고 비대면 가능 은행을
따로 명시한다 — 그 열거가 곧 기관 단위 근거이므로 6곳 모두 카드가 된다.
**새로 수집한 사실은 없다.** 비자별 셀은 이 보도자료의 범위가 아니라 unknown 으로
남는다.

**`fit_score` 산식** (planner §9.2, 기획서 14.3 "기준 공개"):

```
fit_score      = 0.5×visa_fit + 0.3×doc_burden + 0.2×channel_access
visa_fit       = official 1.0 / inferred 0.6 / unknown 0.0
doc_burden     = 1 - (required_docs 수 / 확인된 셀 중 최대 서류 수)
channel_access = 언어지원 0.5 + 비대면 0.3 + 전용지점 0.2
```

★ **미확인을 0 으로 접지 않는다.** `languages_supported: []` 와
`dedicated_branch_count: null` 은 "없다"가 아니라 "확인하지 못했다"이다. 0 으로
계산하면 **확인 못 한 은행이 서비스가 나쁜 은행으로 정렬된다** — 근거 없는
주장을 점수로 만드는 것이다. 미확인 항목은 **분모에서도 빠지고**(가중 평균을
아는 항목끼리만 낸다), 무엇을 확인하지 못했는지가 `unverified` 로 함께 나간다.
아는 항목이 하나도 없으면 `fit_score` 는 `0.0` 이 아니라 `null` 이다.

산식은 `GET /institutions/ranking-policy` 가 **`fit.py` 의 상수를 읽어** 공개한다.
문서용 사본을 두지 않는다 — 두 곳에 적으면 반드시 어긋난다.

> **planner §10-F2 의 "설명 문장만 LLM 생성"은 M1 에서 제외했다.**
> 조회 결과가 대부분 unknown 이라 생성 문장이 정적 문구보다 나을 것이 없는데
> 카드마다 20~45초를 쓰고 vi 는 한국어로 답한다(exp_012 `language_mismatch` 7건).
> 근거와 함께 `docs/spec-changes.md` #26 에 기록했다.

### 4) 출력
소스: `app/schemas/institution.py :: InstitutionsResponse`

| 필드 | 타입 | 설명 |
|---|---|---|
| `results` | `list[InstitutionCard]` | `fit_score` 내림차순 |
| `unknown_institutions` | `list[str]` | ★ 요건 미확인 기관 코드 |
| `disclaimer_tier` | `Tier` | official 근거가 있으면 B, 전무하면 C |
| `updated_at` | `str` | 매트릭스 갱신일 |

`InstitutionCard` 에서 **`status` 와 `account_open` 은 다른 필드다.** 앞은 기관
단위(외국인 채널) 확인 상태이고 뒤는 요청한 체류자격의 계좌개설 요건 상태다.
합치면 "공식 확인됨"이 실제보다 넓게 읽힌다.

`unknown_institutions` 를 카드 배열에 섞지 않고 최상위에 따로 두는 이유도 같다 —
회색으로 칠해 섞으면 "정보가 있는데 좀 흐린 것"으로 읽힌다.

### 5) 화면 연결
S3 `/[locale]/dashboard` → `/[locale]/institutions`
컴포넌트: `InstitutionCard`, `UnknownNotice`, `TierNotice`

### 6) 예외 처리
| 상황 | 처리 |
|---|---|
| 입력 오류 | 열거값 외 → 422 (자유 입력 없음, F1 과 같은 규칙) |
| 검색 실패 | 해당 없음 (검색을 쓰지 않는다) |
| 외부 API 장애 | 해당 없음 (외부 호출이 없다) |
| 계층 C | `unknown` 기관은 카드 하단 "확인 필요" 섹션에 별도 표시 (§4.2) |
| 데이터 결함 | 근거 없는 `official` 셀 → 로드 시점 `ValueError`. 화면에 도달하지 않는다 |

### 7) 응답 계층
계좌개설 요건이 전부 미확인이므로 **A 는 나오지 않는다.** official 근거(모바일
외국인등록증)가 있으므로 B, 그마저 없으면 C.

### 8) 검증 항목
✅ `apps/api/tests/test_matrix.py` **27케이스**
- 로더 불변식 4 (근거 없는 official 은 기관·비자 셀 양쪽에서 거부)
- 배포 매트릭스 5 (6기관 승격 · 비대면 2곳 · 비자 셀 unknown 유지 · 창구 300만원)
- `fit_score` 6 (**미확인이 0 으로 접히지 않음** · 빈 서류가 만점이 되지 않음 ·
  공개 산식이 코드 상수와 일치)
- 서류 라벨 2 · 응답 5 · 엔드포인트 5

## F3. 서류 체크리스트 생성기 — 템플릿

### 1) 목적
**창구에서 그대로 보여주는 용도.** 모국어와 한국어를 2열로 병기해, 이용자가
서류 이름을 한국어로 말하지 못해도 종이를 내밀 수 있게 한다.

### 2) 입력
소스: `app/schemas/checklist.py :: ChecklistRequest`

| 필드 | 타입 | 필수 | 검증규칙 |
|---|---|---|---|
| `lang` | `Lang` | 예 | 열거값 외 422 |
| `visa` | `VisaCode` | 아니오 | 열거값 외 422 |
| `purpose` | `Purpose` (5종) | 아니오 | 열거값 외 422 |
| `inst_code` | `str` | 아니오 | **매트릭스에 없는 코드는 422** |
| `include_ko` | `bool` | 아니오 (기본 `true`) | 창구 제시용이라 기본이 병기다 |

`inst_code` 를 조용히 무시하지 않는 이유: 화면이 엉뚱한 기관을 보여주고 있다는
뜻이므로 드러나야 한다.

### 3) 처리
`corpus/matrix/documents.yaml` + `corpus/glossary/glossary.csv` → 절 3개
(`app/docs/checklist.py`). HTML → WeasyPrint → PDF (`app/docs/pdf_render.py`).

★ **성격이 다른 두 목록을 섞지 않는다.**

| 절 | 출처 | 제출처 |
|---|---|---|
| ① 공통 신분 서류 | 금융위 (모바일 ARC) | — |
| ② 계좌개설·한도해제 증빙 | 금융위 `FSC-ACCOUNT-OPENING-PRACTICE` | 은행 창구 |
| ③ 외국인등록 제출서류 | 법무부 `HIKOREA-ARC-DOCS` | 출입국·외국인청 |

한 표에 놓으면 이용자가 **재학증명서를 들고 은행에 간다.** 발급 기관도 제출처도
다르다.

★ **②의 원문은 "증빙 서류(예시)"다.** 확정 목록이 아니고 은행마다 다르다
(`KFB-LIMIT-ACCOUNT`). 그 사실을 절마다 주의문구로 함께 싣는다. 예시를 확정
목록으로 보여주면 이용자가 창구에서 다른 서류를 요구받는다.

★ **근거가 있는 조합만 적는다.** 금융위 예시 표에 없는 거래목적(학비·생활비·
송금)은 **의도적으로 비어 있고**, 빈 절을 지우지 않는다 — "확인하지 못했다"는
것 자체가 답이다.

★ **주의문구·설명은 3언어를 카탈로그에 함께 둔다.** 이 문구가 문서를 어떻게
읽어야 하는지를 정하는 안전 문구인데, 베트남어 이용자에게 한국어로만 보이면
경고가 전달되지 않는다. 서류명 라벨은 사전(`glossary.csv`)이 소스이며
**LLM 번역에 맡기지 않는다** — "재직증명서"가 "work certificate" 가 되면
이용자가 창구에서 다른 서류를 요구받는다.

조판 CSS 는 `@font-face` + `unicode-range` 를 **쓰지 않는다.** 컨테이너 조판
검증에서 불필요함이 확인됐다(`spec-changes.md` #25) — fontconfig 가 글자마다
폴백한다.

### 4) 출력
- `POST /checklist` → `application/pdf` **스트리밍**. 파일명
  `KBuddy_checklist_E-9_vi_20260820.pdf`, `Cache-Control: no-store`.
  **서버에 저장하지 않는다.**
- `POST /checklist/preview` → `ChecklistResponse` (JSON). 화면 내 HTML 체크리스트용.

두 경로가 **같은 조립 결과**를 쓴다. 갈라 두면 §12.3 폴백에서 내용이 어긋난다.

### 5) 화면 연결
S5-1 `/[locale]/tools/checklist`. F4 가 `next_action.params` 를 쿼리로 넘겨
같은 조건으로 진입한다.

### 6) 예외 처리
| 상황 | 처리 |
|---|---|
| 입력 오류 | 열거값 외·미등록 기관 코드 → 422 |
| 검색 실패 | 해당 없음 |
| 외부 API 장애 | 해당 없음 |
| 계층 C | 확인된 서류가 하나도 없으면 C |
| **조판 불가** | PDF 만 503, **화면 내 체크리스트는 살아 있다** (§12.3) |

★ **WeasyPrint 는 `ImportError` 가 아니라 `OSError` 로 죽는다.** 모듈은 찾지만
그 안에서 `libgobject` 를 dlopen 하다 실패한다(실측: Windows, error 0x7e).

**컨테이너에서 503 이 나오면 Dockerfile 의 조판 의존성이 깨진 것**이다.

### 7) 응답 계층

## F5. 근거 기반 QA 챗봇 — RAG + LLM

전체 개발의 최대 덩어리. planner §6~§8 전체가 이 기능이다.

### 1) 목적
다국어 질의에 대해 **공개된 1차 출처에 근거해서만** 답한다. 근거가 없거나
개별 심사 영역이면 **답하지 않는 것**을 설계로 강제한다.

### 2) 입력
소스: `app/schemas/chat.py :: ChatRequest`

| 필드 | 타입 | 필수 | 검증규칙 |
|---|---|---|---|
| `lang` | `Lang` (ko/en/vi) | 예 | 열거값 외 거절 |
| `message` | `str` | 예 | 1~2,000자 |
| `context` | `SessionContext` | 아니오 | F1 참조 |
| `history` | `list[HistoryTurn]` | 아니오 | **최근 6턴만** — 초과분은 거절하지 않고 절삭 |

히스토리를 거절이 아니라 절삭하는 이유: 클라이언트 버그로 히스토리가 길어졌다는
이유로 이용자의 질문을 실패시킬 이유가 없다.

### 3) 처리
하이브리드. 판정은 전부 규칙, 생성만 LLM (planner §6.1 ①~⑩):

| 단계 | 방식 | 구현 |
|---|---|---|
| ① 입력 가드레일 | 규칙 | ✅ `guardrail/input_filter.py` |
| ② 계층 C 선판정 | 규칙 | ✅ `tiering/rules.py` (0ms, 검색 미실행) — ko·en·vi |
| ③ 질의 정규화 | 사전 + 소형 LLM | ✅ `rag/normalize.py` |
| ④ 하이브리드 검색 | 규칙 | ✅ `rag/retrieve.py` (웜 41ms) |
| ⑤ 리랭킹 | — | **미도입 확정** — RRF 상위 5건 직행 (ADR-001) |
| ⑥ 컨텍스트 조립 | 규칙 | ✅ `rag/context.py` |
| ⑦ 생성 | LLM | ✅ `llm/anthropic_client.py` (키 필요) |
| ⑧ 출력 가드레일 | 규칙 | ✅ `tiering/postprocess.py` |
| ⑨ 계층 최종 확정 | 규칙 | ✅ `tiering/postprocess.py` ★ |
| ⑩ AI 생성 표시 | UI | ✅ `components/common/Notices.tsx` |

②와 ⑨가 이 서비스의 심장이다 — "프롬프트가 아니라 아키텍처로 강제한다"는
주장의 실제 구현체이며, 둘 다 프레임워크 밖 순수 함수로 두어 단위 테스트가 가능하다.

**② 는 공개 언어별로 패턴을 따로 갖는다.** 한동안 한국어·영어만 있었고
베트남어는 "정규화 후 한국어 검색어로 2차 방어"에 기대고 있었는데, 정규화는
검색어를 만드는 것이지 의도를 보존하지 않아 **vi 함정이 계층 A 로 통과했다**
(exp_005). 공개 언어를 늘릴 때는 규칙과 골든셋을 함께 늘려야 한다.

**④ 토크나이저** (구현 완료, `app/rag/tokenize.py`):
- 도메인 복합명사 24종을 고유명사로 등록 — "한도제한계좌"가 한도/제한/계좌로
  쪼개지면 "한도 제한 있는 계좌"류 무관 문서까지 매칭되어 변별력이 사라진다
- 체류자격 코드를 형태소 분석 **전에** 정규식으로 보호. 임베딩만으로는 E-9와
  E-7이 거의 같은 벡터가 되므로, BM25가 둘을 다른 토큰으로 취급하는 것이
  혼동 방지의 핵심이다
- `E-9` / `E9` / `e-9` 를 같은 토큰 `E9` 로 정규화 — 문서와 질의의 표기가 다르다

### 4) 출력
SSE 스트림. 이벤트 순서: `meta` → `token`* → `citations` → (`invalidate`) → `done`

소스: `app/schemas/chat.py :: MetaEvent / TokenEvent / CitationsEvent / InvalidateEvent / DoneEvent`

```jsonc
event: meta
data: {"tier":"A","retrieval":{"top1_score":0.71,"margin":0.12,"n_candidates":20,"stale":false,"via":"glossary"}}

event: token
data: {"t":"Tài "}

event: citations
data: {"items":[{"ref":1,"chunk_id":"FSC-2024-0502-LIMIT#0003","title":"…","publisher":"금융위원회",
                "published_at":"2024-05-02","verified_at":"2026-08-09","url":"https://…","stale":false}]}

event: done
data: {"tier":"A","latency_ms":4120,"ai_generated":true,"fallback_reason":null}
```

> **`meta` 의 tier 는 잠정값이다.** 최종 tier 는 `done` 에서 확정된다. 스트리밍 중
> 출력 검사에 실패하면 `invalidate` 를 보내고 클라이언트가 표시된 텍스트를 폴백
> 카드로 **교체**한다. 이 처리를 빠뜨리면 "차단했다"고 주장하면서 화면엔 환각이
> 남는 사고가 난다.

**구조화 출력의 필드 순서에 설계 의도가 있다** (`app/schemas/llm.py :: LLMAnswer`).
`answer` 가 첫 필드여야 스트리밍에서 본문이 먼저 흘러나온다 — TTFT 1.8초 목표가
여기에 걸려 있다. 단위 테스트로 순서를 고정한다.

### 5) 화면 연결
S4 `/[locale]/chat` — `MessageList`, `CitationBadge`, `TierNotice`, `AiDisclosure`

### 6) 예외 처리
| 상황 | 처리 |
|---|---|
| 입력 오류 | 422. 길이 초과는 절삭이 아니라 거절(2,000자는 정상 질의 범위를 크게 넘음) |
| 검색 실패 | top1 < 0.42 또는 margin < 0.05 → `low_confidence` 폴백 + 1332 안내 |

취급한다.** 임계값 캘리브레이션의 기준이다.

### 7) 응답 계층
A / B / C 전부 생성 가능. 단 C는 **생성하지 않고** 정적 폴백으로 대체한다.

모두 `None` 으로 나간다. **`exceeds=False`("한도 안이다")도 근거 없는 단정**이라
내지 않는다 — 화면에 초록 배지를 붙이면 근거 없는 안심을 주게 된다.

★ **근거 없이 status 를 올릴 수 없다.** `_rule()` 이 status ≠ unknown 인데
`source_url` 이나 값이 없으면 `SystemExit` 를 낸다. 반대로 unknown 인데 값이
채워져 있어도 죽는다 — 그 값이 화면 어딘가로 새어 나가기 때문이다.

### 4) 출력
`app/schemas/remittance.py :: RemittanceResponse`.

★ **`used_is_self_declared` 가 항상 True 다.** 이 서비스는 ORIS 를 조회하지
않는다 — 조회할 수단이 없고, 있는 것처럼 보이면 이용자가 이 숫자를 공식 잔액으로
믿는다(planner §10-F6 4번). 화면은 입력란 바로 아래에 그 사실을 적는다.

★ **환율에 `quoted_at` 이 필수다.** ECOS 는 일별 고시라 실시간이 아니다
(`spec-changes.md` #A). `basis` 는 `"당일 고시 매매기준율"` 로 고정이다.

```jsonc
{
  "amount_krw": 3000000, "amount_usd": 2154.40,
  "rate": { "value": 1392.5, "quoted_at": "2026-08-20",
            "source": "한국은행 ECOS", "basis": "당일 고시 매매기준율",
            "is_stale": true },              // 옛 값을 쓰는 중임을 숨기지 않는다
  "annual":          { "status": "unknown", "limit_usd": null,
                       "remaining_usd": null, "exceeds": null },
  "per_transaction": { "status": "unknown", "exceeds": null },
  "used_is_self_declared": true,
  "disclaimer_tier": "B"
}
```

### 5) 화면 연결
S5-2 `app/[locale]/tools/remittance/page.tsx` · 대시보드 카드 `dashboard.cardRemittance`.

`exceeds === null` 에는 **아무 배지도 붙이지 않는다.** unknown 한도는 "❔ 확인 필요"
로 그리고, 왜 금액이 없는지를 함께 적는다.

### 6) 예외 처리
| 상황 | 동작 |
|---|---|
| `ECOS_API_KEY` 미설정 (이력 없음) | 200 + `rate=null` + 사유. **한도 안내는 그대로 나간다** |
| ECOS 장애·오류(`RESULT.CODE`) | 마지막 성공값 + `is_stale=true` + 화면 경고 |
| 고시일이 3일 초과 | `is_stale=true` (주말·연휴 감안) |
| 1시간 내 재조회 | 캐시 — 외부 호출 없음 |
| `amount_krw <= 0` | 422 |

★ **옛 환율을 조용히 쓰지 않는다.** 재사용하면 `is_stale=true` 가 붙고 화면이
"최신 고시를 가져오지 못해 마지막으로 받은 값을 씁니다"를 띄운다.

### 7) 응답 계층
**항상 B.** 환산과 한도 안내는 통상적 안내다. "내가 얼마까지 보낼 수 있나"는
금융기관 심사이므로 계층 C 이며 `/chat` 에서 거절된다.

### 8) 검증 항목

근거 없는 한도를 만들지 않음(`exceeds` 가 `False` 도 아닌 `None`) · 환율에 항상
기준일 · 마지막 성공값 재사용을 숨기지 않음 · 계산이 순수 함수.

`test_catalog_limits_are_currently_unknown` 은 **지금이 미확인 상태임을 고정**한다 —

✅ **환율은 실키 검증 완료 (2026-08-21).** 1,393.00 원/USD, 고시 2026-08-21,

⚠ **한도는 키가 들어와도 그대로 `unknown` 이다.** 환율은 ECOS 가 주지만 법정 한도는

## F7. 금융상품 비교 — OpenAPI + 정렬

### 1) 목적
금감원 「금융상품 한눈에」 공시로 **상품 조건**을 비교한다. 가입 가능 여부를
판단해 주는 기능이 아니다 — 그 구분이 7)에 걸려 있다.

### 2) 입력
소스: `app/routers/products.py`

| 필드 | 타입 | 필수 | 검증규칙 |
|---|---|---|---|
| `lang` | `Lang` | 아니오 (기본 `ko`) | 열거값 외 422 |
| `kind` | `deposit`\|`saving`\|`credit_loan` | 아니오 (기본 `deposit`) | 열거값 외 422 |
| `save_trm` | `str` | 아니오 | 예·적금에만 의미. 없으면 기간이 섞인다 |
| `limit` | `int` | 아니오 (기본 20) | 1~100 |

### 3) 처리
FSS 8종 중 **정기예금·적금·신용대출 3종만**. `baseList` + `optionList` 를
`(fin_co_no, fin_prdt_cd)` 로 조인한다.

| 단계 | 구현 |
|---|---|
| 조회·캐시 | `tools/fss_client.py :: fetch()` — 하루 1회 |
| 조인·필터·정렬 | `tools/product_compare.py :: build_cards()` |
| 기준 공개 | `tools/product_compare.py :: sort_policy()` |

★ **선택한 기간의 금리가 없는 상품은 목록에서 뺀다.** 남기면 금리 칸이 빈
카드가 되고, 빈 칸은 화면에서 "0%"로 읽힌다.

★ **공시 없는 금리를 0 으로 접지 않는다.** `""`/`None` 을 0.0 으로 접으면
**공시하지 않은 대출이 금리 0% 로 1위**가 된다. `sort_value=None` 으로 두고
목록 맨 뒤에 놓는다 — F2 의 `unverified` 와 같은 함정이고 같은 해법이다.

### 4) 출력
`app/schemas/product.py :: ProductsResponse`.

★ **`available` 이 `results` 와 별도로 있다.** 외부가 죽었거나 키가 없을 때 빈
목록을 돌려주면 화면이 "그런 상품이 없다"로 그린다. 못 가져온 것과 없는 것은
다르다. 그래서 502 도 내지 않는다 — 502 는 "우리 서비스가 고장났다"로 읽힌다.

정렬 기준은 `GET /products/sort-policy` 와 응답 안 `sort_policy` **양쪽**으로
공개한다 (기획서 14.3). 정렬에 들어가는 값은 공시 금리 하나뿐이고, 들어가지
않는 것(`제휴 여부`·`광고비`·`수수료 수취`·`은행 규모`·`조회수`)을 함께 싣는다.

```jsonc
{
  "kind": "deposit", "save_trm": "12", "available": true,
  "results": [
    { "company": "다라은행", "product": "다라 e-예금",
      "join_deny": "3",              // 원문 코드 그대로. 외국인 가입 여부가 아니다
      "sort_value": 4.10,
      "options": [ { "save_trm": "12", "rate": 3.30, "rate_max": 4.10 } ] },
    { "company": "마바은행", "product": "마바 미공시예금",
      "sort_value": null }           // 0% 가 아니라 "공시 없음" — 맨 뒤
  ],
  "sort_policy": { "sort_input": "intr_rate2", "direction": "desc",
                   "excluded_inputs": ["제휴 여부", "광고비", "수수료 수취", …] },
  "disclaimer_tier": "B"
}
```

### 5) 화면 연결
`app/[locale]/tools/products/page.tsx` · 대시보드 카드 `dashboard.cardProducts`.

상품 종류 탭 3개 + 저축기간 선택(예·적금). 주의문구가 목록보다 **위**에 상시로
있고, `available=false` 는 빈 목록과 **다른 문구**로 그린다.

### 6) 예외 처리
| 상황 | 동작 |
|---|---|
| `FSS_API_KEY` 미설정 | 200 + `available=false`, 사유 `FSS_API_KEY 미설정` |
| 외부 장애·타임아웃(5초) | 200 + `available=false` |
| `err_cd != "000"` (010 키오류 / 020 횟수초과 / 900 데이터없음) | 200 + `available=false` + 코드 |
| 같은 날 재조회 | 캐시 — 외부 호출 없음 (일일 허용횟수 방어) |

### 7) 응답 계층
**항상 B.** 공시값 자체는 공식이지만 "당신이 가입할 수 있는가"는 기관 심사라
A 로 올릴 수 없다.

★ **이 API 는 외국인 가입 가능 여부를 제공하지 않는다.** `join_deny`(1/2/3)와
`join_member` 는 체류자격을 다루지 않는다. `join_deny=1`("제한없음")을 "외국인도
가능"으로 옮기는 순간 그것이 환각이다. 원문 코드를 **그대로** 싣고, 가입 가능
여부는 화면·`sort_policy` 양쪽에서 "해당 금융기관에 직접 확인"으로 명시한다.

### 8) 검증 항목
`apps/api/tests/test_products.py` (14개). **실키 없이 돈다** —
`fetch(fetcher=...)` 에 픽스처를 주입해 조인·정렬·경계를 검증하므로, 키가 들어올
때까지 이 코드가 미검증으로 남지 않는다. 지키는 주장 넷: 못 가져온 것 ≠ 없는 것 ·
공시 없는 값을 0 으로 접지 않음 · 정렬 입력에 제휴·수수료 없음 · 외국인 가입
가능 여부를 만들어 내지 않음.

✅ **실키 검증 완료 (2026-08-21).** 예금 38종 · 적금 59종 · 신용대출 44종.

★ 실데이터에서 **픽스처가 잡지 못한 오류 하나**가 드러났다. `optionList` 는 상품당
금리를 4종류(A 대출금리 / B 기준 / C 가산 / D 가감조정) 보내는데, 구분 없이 최저값을
고르면 **가감조정금리(0.5%)가 대출금리로 표시된다.** 실제로 상위 3건이
0.01%·0.02%·0.1% 로 나왔다 — 실재하지 않는 신용대출 금리다.
`crdt_lend_rate_type == "A"` 만 쓰도록 고쳤고(41종 전부 A 보유) 회귀 테스트를 붙였다.

★ **`http` 로는 동작하지 않는다.** 문서 예제는 http 지만 서버가 https 로 307 을 내고
`httpx` 는 리다이렉트를 따라가지 않는다. 무엇보다 인증키가 쿼리스트링에 실리므로
평문으로 보낼 값이 아니다 — `BASE_URL` 은 https 다.

## F8. 다국어 사기 유형 대조 — 체크리스트

### 1) 목적
겪은 상황을 **공식 자료에 실린 유형과 대조**하게 한다. 판정해 주는 것이 아니라
대조표를 주는 것이며, 그 구분이 이 기능의 전부다.

### 2) 입력
소스: `app/routers/scam.py`

| 필드 | 타입 | 필수 | 검증규칙 |
|---|---|---|---|
| `lang` | `Lang` | 아니오 (기본 `ko`) | 열거값 외 422 |

★ **사연을 받는 인자가 없다.** "이 전화가 사기인가요?"를 실어 보낼 수 있는
파라미터를 두면 그 순간 계층 C 설계가 무너진다. 체크 상태도 **서버로 보내지
않는다** — 브라우저 안에서만 센다.

### 3) 처리
정적 카탈로그 조회 + 화면 체크박스 매칭. **LLM 이 없다.**

| 단계 | 구현 |
|---|---|
| 카탈로그 로드 | `matrix/scam.py :: _raw()` — `corpus/matrix/scam.yaml` |
| 언어 선택 | `util/i18n_text.py :: localized()` (F3 와 **같은 함수**) |
| 조립 | `matrix/scam.py :: build_response()` |
| 체크 매칭 | `app/[locale]/tools/scam/page.tsx` — 클라이언트 상태 |

★ **사기 여부를 판정하지 않는다.** 개수를 판정으로 바꾸는 임계값(예: 3개 이상
이면 사기)을 두지 않는다. 그 한 줄이 화면을 판정기로 만들고, 2개를 체크한
이용자는 "사기가 아니다"로 읽는다.

★ **근거 없는 항목은 기동에서 막는다.** `_evidence()` 가 `source_url` 없는
항목에서 `SystemExit` 를 낸다. 사기 수법 목록은 "여기 없으면 안전하다"로 읽히기
쉬워서, 지어낸 항목 하나가 목록 전체의 신뢰를 무너뜨린다.

### 4) 출력
`app/schemas/scam.py :: ScamResponse`. **판정 필드가 없다** — `verdict`,

      "title": "수사기관·금융기관을 사칭해 정보나 돈을 요구",
