# K-Buddy 기능명세서

> **제출물.** 개발과 동시에 갱신한다 — 기능 하나를 구현할 때마다 해당 절을 채운다.
> 마지막에 몰아 쓰면 8주 차에 반드시 터진다(planner §1.2).

각 기능은 아래 8항목 고정 서식을 따른다. **미구현 기능도 헤더를 비워 두지 않고
남겨 둔다** — 빈 절이 보여야 남은 작업량이 눈에 들어온다.

```
1) 목적   2) 입력   3) 처리   4) 출력
5) 화면 연결   6) 예외 처리   7) 응답 계층   8) 검증 항목
```

**2)·4)의 소스는 Pydantic 스키마다** (`apps/api/app/schemas/`). 필드명·타입·필수여부는
스키마에서 옮겨 적고, 스키마에 나타나지 않는 것(검증규칙의 *이유*, 예외 판단 근거)만
손으로 쓴다. 스키마를 바꾸면 이 문서도 함께 바꾼다.

마지막 갱신: 2026-08-12 · 상태: **F1·F5 완료 / 나머지 골격만**

## F1. 다국어 온보딩 — 규칙 기반

### 1) 목적
이용자의 체류자격·거래목적을 파악해 이후 모든 안내를 개인화한다. 동시에
**수집 범위를 여기서 못 박아** 서비스 전체가 식별정보를 다루지 않도록 만든다.

### 2) 입력
소스: `app/schemas/chat.py :: SessionContext`

| 필드 | 타입 | 필수 | 검증규칙 |
|---|---|---|---|
| `nationality` | `str` (ISO 3166-1 alpha-2) | 아니오 | 정확히 2자, 대문자로 정규화 |
| `visa` | `VisaCode` (12종 열거) | 아니오 | 열거값 외 거절 |
| `stay` | `StayPeriod` (4구간) | 아니오 | 열거값 외 거절 |
| `purposes` | `list[Purpose]` | 아니오 | 최대 5개 |

**자유 입력 필드가 하나도 없다.** 전부 선택지다. 개인정보 최소 수집(§5.1)의
구현이자, 프롬프트 인젝션 표면을 온보딩 단계에서 0으로 만드는 설계다.

전 항목 선택 사항인 이유: 프로필 없이도 일반 안내는 가능해야 하고, 입력을
강제하면 첫 화면에서 이탈한다. 프로필이 비면 검색 메타데이터 필터만 해제된다.

**체류자격 12종 선정 근거** (2026-06, `corpus/stats/moj_24_…csv`):
12종 합계 1,973,900명 = 체류외국인의 68.7%. 빠진 상위는 B-2·C-3·B-1로
전부 단기체류라 계좌개설 대상이 아니다. 확장 후보는 F-3(동반, 84,976명).

### 3) 처리
규칙 기반. LLM 개입 없음.

### 4) 출력
`sessionStorage` 에 저장된 `SessionContext`. **서버로 전송되지만 저장되지 않는다.**
매 `/chat` 요청 body 에 실려 오며 서버는 요청 처리 후 폐기한다.

### 5) 화면 연결
S1 `/[locale]` (언어 선택) → S2 `/[locale]/profile` (`StepSelect` ×4, 진행률 바)

### 6) 예외 처리
| 상황 | 처리 |
|---|---|
| 입력 오류 | 열거값 외 → 422. 클라이언트가 해당 스텝으로 되돌림 |
| 검색 실패 | 해당 없음 |
| 외부 API 장애 | 해당 없음 |
| 계층 C | 해당 없음 |
| `localStorage` 오사용 | **금지.** 공용 PC 대비 — `sessionStorage` 만 사용 |

### 7) 응답 계층
해당 없음 (생성 없음).

### 8) 검증 항목
⬜ 골든셋 문항 미할당 — 규칙 기반이라 단위 테스트로 대체 예정

## F5. 근거 기반 QA 챗봇 — RAG + LLM

전체 개발의 최대 덩어리. planner §6~§8 전체가 이 기능이다.

### 1) 목적
다국어 질의에 대해 **공개된 1차 출처에 근거해서만** 답한다. 근거가 없거나
개별 심사 영역이면 **답하지 않는 것**을 설계로 강제한다.

### 2) 입력
소스: `app/schemas/chat.py :: ChatRequest`

| 필드 | 타입 | 필수 | 검증규칙 |
|---|---|---|---|
| `lang` | `Lang` (ko/en/vi) | 예 | 열거값 외 거절 |
| `message` | `str` | 예 | 1~2,000자 |
| `context` | `SessionContext` | 아니오 | F1 참조 |
| `history` | `list[HistoryTurn]` | 아니오 | **최근 6턴만** — 초과분은 거절하지 않고 절삭 |

히스토리를 거절이 아니라 절삭하는 이유: 클라이언트 버그로 히스토리가 길어졌다는
이유로 이용자의 질문을 실패시킬 이유가 없다.

### 3) 처리
하이브리드. 판정은 전부 규칙, 생성만 LLM (planner §6.1 ①~⑩):

| 단계 | 방식 | 구현 |
|---|---|---|
| ① 입력 가드레일 | 규칙 | ✅ `guardrail/input_filter.py` |
| ② 계층 C 선판정 | 규칙 | ✅ `tiering/rules.py` (0ms, 검색 미실행) — ko·en·vi |
| ③ 질의 정규화 | 사전 + 소형 LLM | ✅ `rag/normalize.py` |
| ④ 하이브리드 검색 | 규칙 | ✅ `rag/retrieve.py` (웜 41ms) |
| ⑤ 리랭킹 | — | **미도입 확정** — RRF 상위 5건 직행 (ADR-001) |
| ⑥ 컨텍스트 조립 | 규칙 | ✅ `rag/context.py` |
| ⑦ 생성 | LLM | ✅ `llm/anthropic_client.py` (키 필요) |
| ⑧ 출력 가드레일 | 규칙 | ✅ `tiering/postprocess.py` |
| ⑨ 계층 최종 확정 | 규칙 | ✅ `tiering/postprocess.py` ★ |
| ⑩ AI 생성 표시 | UI | ✅ `components/common/Notices.tsx` |

②와 ⑨가 이 서비스의 심장이다 — "프롬프트가 아니라 아키텍처로 강제한다"는
주장의 실제 구현체이며, 둘 다 프레임워크 밖 순수 함수로 두어 단위 테스트가 가능하다.

**② 는 공개 언어별로 패턴을 따로 갖는다.** 한동안 한국어·영어만 있었고
베트남어는 "정규화 후 한국어 검색어로 2차 방어"에 기대고 있었는데, 정규화는
검색어를 만드는 것이지 의도를 보존하지 않아 **vi 함정이 계층 A 로 통과했다**
(exp_005). 공개 언어를 늘릴 때는 규칙과 골든셋을 함께 늘려야 한다.

**④ 토크나이저** (구현 완료, `app/rag/tokenize.py`):
- 도메인 복합명사 24종을 고유명사로 등록 — "한도제한계좌"가 한도/제한/계좌로
  쪼개지면 "한도 제한 있는 계좌"류 무관 문서까지 매칭되어 변별력이 사라진다
- 체류자격 코드를 형태소 분석 **전에** 정규식으로 보호. 임베딩만으로는 E-9와
  E-7이 거의 같은 벡터가 되므로, BM25가 둘을 다른 토큰으로 취급하는 것이
  혼동 방지의 핵심이다
- `E-9` / `E9` / `e-9` 를 같은 토큰 `E9` 로 정규화 — 문서와 질의의 표기가 다르다

### 4) 출력
SSE 스트림. 이벤트 순서: `meta` → `token`* → `citations` → (`invalidate`) → `done`

소스: `app/schemas/chat.py :: MetaEvent / TokenEvent / CitationsEvent / InvalidateEvent / DoneEvent`

```jsonc
event: meta
data: {"tier":"A","retrieval":{"top1_score":0.71,"margin":0.12,"n_candidates":20,"stale":false,"via":"glossary"}}

event: token
data: {"t":"Tài "}

event: citations
data: {"items":[{"ref":1,"chunk_id":"FSC-2024-0502-LIMIT#0003","title":"…","publisher":"금융위원회",
                "published_at":"2024-05-02","verified_at":"2026-08-09","url":"https://…","stale":false}]}

event: done
data: {"tier":"A","latency_ms":4120,"ai_generated":true,"fallback_reason":null}
```

> **`meta` 의 tier 는 잠정값이다.** 최종 tier 는 `done` 에서 확정된다. 스트리밍 중
> 출력 검사에 실패하면 `invalidate` 를 보내고 클라이언트가 표시된 텍스트를 폴백
> 카드로 **교체**한다. 이 처리를 빠뜨리면 "차단했다"고 주장하면서 화면엔 환각이
> 남는 사고가 난다.

**구조화 출력의 필드 순서에 설계 의도가 있다** (`app/schemas/llm.py :: LLMAnswer`).
`answer` 가 첫 필드여야 스트리밍에서 본문이 먼저 흘러나온다 — TTFT 1.8초 목표가
여기에 걸려 있다. 단위 테스트로 순서를 고정한다.

### 5) 화면 연결
S4 `/[locale]/chat` — `MessageList`, `CitationBadge`, `TierNotice`, `AiDisclosure`

### 6) 예외 처리
| 상황 | 처리 |
|---|---|
| 입력 오류 | 422. 길이 초과는 절삭이 아니라 거절(2,000자는 정상 질의 범위를 크게 넘음) |
| 검색 실패 | top1 < 0.42 또는 margin < 0.05 → `low_confidence` 폴백 + 1332 안내 |
| 외부 API 장애 | 재시도 2회 → `claude-opus-5` 폴백 → 그래도 실패 시 `upstream_error` |
| 모델 거절 | `stop_reason=refusal` → `model_refusal`. **`content` 를 읽기 전에 분기** |
| 계층 C | 검색 전 선판정에서 차단. 생성 호출 자체를 하지 않음 |

**거짓 폴백(답할 수 있는데 안 함)보다 거짓 생성(근거 없이 답함)을 훨씬 무겁게
취급한다.** 임계값 캘리브레이션의 기준이다.

### 7) 응답 계층
A / B / C 전부 생성 가능. 단 C는 **생성하지 않고** 정적 폴백으로 대체한다.
계층 강등 규칙(§7.4): 근거가 government 가 아니면 A→B, stale 문서가 있으면 A→B.

### 8) 검증 항목
✅ 골든셋 **160문항** (ko 77 / en 42 / vi 41). 240 확장 예정.
자동 채점 하니스 `eval/run_eval.py` — 서버 없이 파이프라인을 직접 호출한다.

100 → 160 확장은 **측정이 못 하던 곳**을 채웠다. 근거 없는 질의(`no_evidence`)
표본이 en 2건 / vi 1건뿐이라 두 언어의 임계값이 사실상 신뢰 구간 없이 잡혀
있었다 — 확장분 60건 중 19건을 여기에 썼다 (en 2→10 / vi 1→10).

`exp_002` (2026-08-12, llm 모드 전량):

| 지표 | 값 | 목표 |
|---|---:|---:|
| 근거 인용률 | **100%** (43/43) | 100 |
| Recall@5 | **93.8%** (61/65) | 92 |
| 폴백 정확도 | **100%** (35/35) | 95 |
| 숫자 정확도 | **100%** (43/43) | 98 |
| 사실 포함률 | 91.1% | 90 |
| 금지표현 | **0건** | 0 |
| 과잉 폴백률 | 33.8% ★ | ≤8 |
| 계층 일치율 | 74.4% ★ | 90 |
| 지연 p50 / p95 | 6,184 / 17,761 ms ★ | p95 ≤6,000 |

★ 3종은 미달이다. 과잉 폴백은 게이트 과녁을 바로잡아 재보정했고(ADR-001),
지연과 숫자 대조의 과잉 차단은 **미해결**이다.

현재 확보된 검증: **테스트 345개** + 골든셋 160문항 + M1 검증 12항목.
- 숫자 대조 43케이스 (`test_numerals.py`)
- 계층 판정·가드레일 94케이스 (`test_tiering.py`)
- 파이프라인·SSE 29케이스 (`test_pipeline.py`)
- 스트리밍 파서 25케이스 (`test_partial_json.py`)
