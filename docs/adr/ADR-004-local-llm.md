# ADR-004 — 로컬 생성 모델 (노선 확정, 모델 실측 대기)

- 상태: **노선 확정 / 모델 실측 대기** — 로컬 생성 + AWS 서울 리전으로 간다.
  하이브리드·API 복귀는 **폴백으로 강등**했다. 남은 것은 모델 확정이고
  **판정은 CUDA bf16 실측으로만** 한다.
- ⚠ **부분 대체됨 — [ADR-005](ADR-005-cuda-only-dev.md) (2026-08-19).**
  이 문서의 **"개발 mps / 배포 cuda" 이중 경로 결정은 더 이상 유효하지 않다.**
  개발·판정 모두 로컬 CUDA(RTX 5060 Ti 16GB)에서 bf16 으로 돌고, MPS 경로는
  코드에서 제거했다. 아래에 남은 MPS 관련 서술(스크리닝/판정 분리, int8 이월,
  "AWS GPU 가 있어야 판정된다")은 **그 결정에 이르게 된 근거로서 보존**한 것이며
  현재 상태가 아니다. 나머지(로컬 생성 노선, 후보 3종, 판정 기준)는 유효하다.
- 날짜: 2026-08-12 (갱신 2026-08-18 · 부분 대체 2026-08-19)
- 관련: ADR-002(생성 LLM 선정) · ADR-001(리랭커) · planner §2.3, §14.1, §15.2 ·
  [로컬 생성 노선 확정 및 모델 비교 계획](../2026-08-17-local-llm-plan.md) ·
  [모델 슬림화](../2026-08-18-model-slimming.md)

## 맥락

ADR-002 는 "감수하는 것"으로 **국내 리전 원칙 미충족**을 적어 두었다.
Anthropic API 가 해외 리전이기 때문이다. 생성을 로컬 모델로 내리고 배포를
**AWS 서울 리전(ap-northeast-2)** 으로 옮기면, planner §15.2 의 `LLM_REGION=kr`
은 문구 수정이 아니라 **실제로 충족**된다. 금융 도메인에서 데이터 주권은
서술로 덮을 수 있는 종류가 아니다.

비용은 부차적 동기다 — 골든셋 160문항 1회가 $1.59 로, 재충전으로 끝나는 문제다.

## 결정

**런타임: PyTorch + transformers + XGrammar, 단일 코드 경로**
(개발 `device=mps`, 배포 `device=cuda`).

vLLM 은 처리량이 좋지만 **MPS 를 지원하지 않아 개발과 배포가 갈라진다.**
이 프로젝트는 컨테이너 기동 실패와 조판에서 "로컬에선 됐는데" 사고를 이미
두 번 겪었다. 단일 사용자 데모라 처리량은 병목이 아니다.

**모델: `Qwen/Qwen3.5-4B`** (2026-08-17 교체. 이전 값은 `Qwen/Qwen3-4B-Instruct-2507`).

> **Gemma 3 는 gated repo 라 401** — 라이선스 동의와 HF 토큰이 필요해 측정에서
> 제외했다. 접근이 열리면 비교군에 넣는다. 한국어 특화 소형 모델
> (EXAONE·HyperCLOVAX·Kanana)은 **ko/en 전용이라 후보가 아니다** — 공개 언어에
> 베트남어가 있다.

### 🔄 2026-08-17~18 — 모델 교체와 기본 백엔드 전환

`Qwen/Qwen3.5-4B` 로 바꾸고 **기본 백엔드를 `local` 로 돌렸다**(`config.py:63,100`).
배선 검증(`scripts/verify_local_model.py`) 6개 검사를 M3 Pro/mps/fp16 에서 전부
통과했다 — 로드 OK, XGrammar 컴파일 1.4초, 문법 제약 생성에서 `citations` 와
`numbers_used` 정상. **아래 ① 의 생략 사고가 이 모델에서는 재현되지 않는다.**

`local_model` 기본값이 `google/gemma-3-4b-it` 로 남아 있었는데, **gated 라 401 로
막혀 이미 측정에서 제외된 값**이었다. 즉 `LLM_BACKEND=local` 을 켜면 가중치를 받다
죽는 상태였다. `AnthropicClient` 는 그대로 남으므로 실측이 미달이면
`LLM_BACKEND=anthropic` 한 줄로 되돌아가고, exp_002~005 의 재현성도 유지된다.

**측정 세트·메모리 예산·장치 전략·선정 게이트는 계획서에 있다**(§2·§3·§6·§8).
여기서 중복하지 않는다. 요지만:

- 1차 3종 — Qwen3.5-4B(계열 연속성) · Gemma-4-E4B-it(MatFormer 효율) ·
  Sailor2-8B-Chat(SEA 특화 SFT). **8B 두 후보는 18GB 통합메모리에 올라가지 않아
  첫 검증을 AWS 에서 한다 — 탈락이 아니다.**
- `Gemma-4-E2B-it` 제외 — VRAM 이 Qwen3.5-4B 와 같은데 품질이 낮다(지배당함).
- `Qwen-SEA-LION-v4-4B-VL` 은 2차 조건부 — VL 이라 모델 클래스·`vocab_size` 위치
  때문에 코드 수정이 필요할 수 있다.
- **MPS 는 스크리닝, CUDA 는 판정.** dtype 이 장치마다 달라(mps fp16 / cuda bf16)
  두 수치를 같은 표에 놓을 수 없다.

## 측정으로 확정된 사실

### ① 구조화 출력 — 선택 필드는 문법이 생략을 허용한다 ★

가장 중요한 발견이다. `LLMAnswer.citations` 는 `default_factory=list` 라 JSON
스키마의 `required` 에 들어가지 않는다. 문법은 그걸 그대로 반영해 **생략을
허용**하고, Qwen3-4B 는 `answer`·`tier`·`numbers_used` 를 채운 뒤
**`citations` 를 통째로 건너뛰었다.**

결과: 인용 0건 → 후처리가 차단 → **정상 답변이 `no_citation` 폴백**이 된다.

Anthropic 경로가 멀쩡했던 것은 **Claude 가 지시를 따라 채웠기 때문이지 스키마가
강제해서가 아니다.** 모델의 선의에 기대고 있던 자리였고, 모델을 바꾸자 드러났다.

→ 문법 컴파일 직전에 모든 속성을 `required` 로 만든다(`_require_all_fields`).
   **Pydantic 모델은 건드리지 않는다** — 파이썬 쪽 입력 관용은 유지하고 생성
   문법만 엄격하게 한다. 회귀 테스트 3종.

### ② `answer` 가 첫 필드인 설계가 길이와 충돌한다

`answer` 를 스키마 첫 필드에 둔 것은 스트리밍 TTFT 를 위한 의도적 설계다
(`app/schemas/llm.py`). 그런데 본문이 길면 `max_new_tokens` 를 소진해
**뒤따르는 `citations`·`numbers_used` 가 생성되기 전에 잘린다** — 역시
`no_citation` 폴백이다. **길이가 곧 차단 사유가 되는 구조**다.

→ `local_max_new_tokens` 1024 → 2048, 시스템 프롬프트에 **3~5문장·400자** 명시.
   "짧게"라는 지시만으로는 소형 모델이 길게 쓴다.

### ③ 정규화 품질 — 로컬이 낮다

Recall@5 (골든셋 160문항 중 해당 언어):

| | API (haiku) | 로컬 (Qwen3-4B) | 목표 |
|---|---:|---:|---:|
| en | 95.5% | **86.4%** | ≥92 |
| vi | 95.2% | **90.5%** | ≥92 |

프롬프트의 `E-9` **예시**를 Qwen3 가 **지시**로 읽어 질문에 없는 E-9 를 모든
검색어에 주입하던 것을 고쳐 vi 를 81.0% → 90.5% 로 올렸다. 둘 다 목표 미달이다.

#### 🔄 2026-08-18 — Qwen3.5-4B 는 vi 를 **개선하지 못했다**

계획서 §2.1 이 Qwen3.5-4B 에 건 가설은 "계열 연속성 — 201개 언어 공식 지원이
SEA 특화 SFT 없이도 vi 를 충족하는가" 였다. 같은 자(vi 골든 21문항)로 쟀다:

| | API (haiku) | Qwen3-4B | **Qwen3.5-4B** | 목표 |
|---|---:|---:|---:|---:|
| vi Recall@5 | 95.2% | 90.5% (19/21) | **90.5% (19/21)** | ≥92 |

**한 문항도 움직이지 않았다.** 신형 백본의 광범위 다국어만으로는 vi 정규화가
목표에 닿지 않는다 — 계획서 §2 가 대립시킨 "신형 백본의 광범위 다국어 vs
구세대 백본의 SEA 집중 학습" 에서, 전자가 단독으로는 부족하다는 쪽의 증거다.
**Sailor2-8B-Chat(SEA SFT)의 값어치를 재는 것이 그만큼 중요해졌다.**

> 측정 조건: `run_eval.py --no-generation --lang vi` (③ 정규화만 실행).
> Recall@5 는 ③ 에만 의존하고 임계값에도 의존하지 않아(계획서 §5) llm 모드
> 수치와 직접 비교할 수 있다. 리포트
> `eval/reports/exp_009_qwen35-4b-textonly_mps_nogen.json`.
> Qwen3-4B 쪽 수치의 출처는 아래 표이며, 그 실행의 리포트 파일은 유실됐다
> (exp_006 — 측정은 유효, 산출물만 없음).
>
> **en 은 아직 재지 않았다.** 목표 미달분(86.4%)이 더 큰 쪽이라 AWS 실측에
> 반드시 포함해야 한다.

> **용어표 주입은 시도했다가 되돌렸다.** 코퍼스 표준 용어 35개를 보여 주면
> 어휘가 수렴할 것으로 봤고 개별 검색어는 정확해졌다("한도제한계좌").
> 그런데 Recall@5 가 **떨어졌다**(en 59.1%, vi 76.2%) — 검색어가 짧고 좁아져
> dense 정보량과 BM25 후보 폭이 함께 줄었다. **용어가 정확한 것과 검색이 잘
> 되는 것은 다른 문제였다.**

### ④ 지연 — MPS 는 개발 도구이지 제품이 아니다

M3 Pro / MPS / Qwen3-4B fp16, **문법 없이도 11.4 tok/s**. XGrammar 가 병목이
아니라 장치 자체의 속도다.

| 질의 | 총 지연 | TTFT |
|---|---:|---:|
| ko (근거 5건) | 125.0s | 41.7s |
| en | 55.6s | 23.1s |
| vi | 42.2s | 15.5s |
| 계층 C 함정 | **0.0s** | — (규칙이 LLM 이전에 차단) |

**골든셋 160문항 전량 채점은 MPS 에서 4~6시간이 걸려 사실상 불가능하다.**
계획했던 결정 게이트를 로컬에서 실행할 수 없다 — **AWS GPU 가 있어야 판정된다.**

## 아직 결정하지 않은 것

- **모델 크기·최종 채택**: 4B 로 정규화가 목표 미달이고, Qwen3.5-4B 로 올려도
  vi 는 움직이지 않았다(③ 갱신). 1차 3종을 CUDA 에서 전량 채점해 판단한다.
- **양자화 채택 여부**: int8 은 크기 −42% 와 ③ 정규화 품질 유지를 확인했으나
  **MPS 에서 8.7배 느려 지연을 판정하지 못했다.** CUDA 에서 잰다
  ([슬림화 문서](../2026-08-18-model-slimming.md) §4.3·§6.2).
- ~~**지연 목표**~~ — **결정됨 (2026-08-20): TTFT 로 재정의한다.**
  총 완료 P95 6초는 생성이 API(haiku)일 때 잡은 값이고, 로컬 4B 실측은
  p50 21.8초 / **p95 44.7초**(exp_012)다. 모델을 바꿔도 한 자릿수로 내려오지
  않는다. planner §14.2 가 애초에 **TTFT 를 별도 지표로** 두라고 했고
  계측(`ttft_ms`)도 이미 있다 — **TTFT p50 3.5초 / p95 18.4초**(exp_012)를
  공개 지표로 삼는다.

  총 완료 시간은 **참고 지표로 계속 기록한다.** 목표에서 빼는 것이지 재는 것을
  멈추는 것이 아니다 — 모델이 바뀌면 여기가 먼저 움직인다.
  근거와 조치는 `docs/spec-changes.md` #27.

> **하이브리드·API 복귀는 폴백으로 강등했다**(계획서 §1). 1차 3종이 전원
> 미달이면 Qwen3.5-9B 승격, 그래도 미달이면 **정규화만 API(haiku)** 로 되돌린다.
> 그 경우 "외부로 나가는 것이 없다"는 성립하지 않고 ADR-002 의 원래 서술
> ("외부로 나가는 것은 생성 호출 하나뿐")로 돌아간다.

## 현재까지의 판단

**정확성 경로는 살아 있다.** 문법 제약으로 형식이 보장되고, 필수 필드를 강제한
뒤로는 인용·수치가 정상적으로 생성된다(계층 A/B 판정, `numbers_used`
["30만원","100만원","300만원"] 정확). 계층 C 함정은 규칙이 0.0초에 차단한다.

**남은 것은 성능과 정규화 품질이며, 둘 다 하드웨어·모델 크기의 함수다.**
그래서 이 ADR 은 지금 확정하지 않는다 — 확정할 근거가 아직 없다.
