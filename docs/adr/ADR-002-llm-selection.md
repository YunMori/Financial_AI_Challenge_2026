# ADR-002: 생성 LLM 선정 — Anthropic Claude Sonnet 5

- 상태: **채택**
- 날짜: 2026-08-12
- 관련: planner §2.3, §15.2 / `docs/dev-log.md` 2026-08-11·08-12

## 맥락

생성 모델을 확정해야 한다. planner §2.3은 "한국어 규제문서 이해도 / 대상 언어
생성 품질 / 구조화 출력 안정성 / 지연·단가"를 점수화해 3주 차에 정하도록
설계했으나, 개인 참가 일정에서 계정을 여러 개 열고 병렬 평가하는 것은 비현실적이다.
확보된 키는 Anthropic 하나다.

## 결정

**1순위 `claude-sonnet-5`, 장애·거절 시 `claude-opus-5` 로 폴백.**

질의 정규화(§6.2 3단)는 `claude-haiku-4-5`.

### 폴백 방향을 위로 잡은 이유

폴백은 드물게 발동한다. 그 순간에는 비용보다 **성공률**이 중요하고, opus-5는
별도 용량 풀이라 sonnet 쪽 장애를 실제로 회피할 수 있다. haiku로 내리면
장애 상황에서 답변 품질까지 함께 떨어져 폴백의 의미가 없다.

### 호출 파라미터

| 항목 | 값 | 근거 |
|---|---|---|
| `effort` | `medium` | sonnet-5 기본값 `high`는 §14.1 지연 예산 초과. `low`는 `numbers_used` 누락 위험 — 누락되면 숫자 대조가 통과는 하되 아무것도 못 잡는다 |
| `thinking` | `adaptive` | 미지정 시 기본값. 지연이 문제면 thinking을 끄는 대신 effort를 내린다 |
| `cache_control` | 시스템 프롬프트에만 | 근거는 매 요청 바뀌므로 user 메시지에. **하한 1,024토큰** |
| 구조화 출력 | `LLMAnswer` JSON 스키마 | `answer`가 첫 필드 — 스트리밍 순서를 결정한다 |

## 감수하는 것 — 국내 리전 원칙 미충족

**planner §15.2의 `LLM_REGION=kr` 은 충족할 수 없다.** Anthropic API는 해외 리전이다.

이 사실을 문구로 덮지 않는다. 대신 **실제로 참인 서술로 교체**한다:

> 임베딩·벡터DB·BM25·입출력 가드레일·계층 판정이 전부 로컬에서 실행되고,
> 외부로 나가는 것은 **생성 호출 하나뿐**이다.

이건 축소된 주장이 아니라 더 정확한 주장이다. 이 서비스의 안전성 주장
(근거 기반, 계층 판정, 환각 차단)은 전부 규칙 기반 로컬 코드에 있고, 외부
모델은 "주어진 근거를 대상 언어로 요약하는" 역할만 한다. 모델을 교체해도
안전 속성이 유지된다는 뜻이며, 그 편이 발표에서 더 강한 이야기다.

### 후속 조치

- `.env.example` 에서 `LLM_REGION` 삭제 — **완료**
- 기획서 §15.2 문구 수정 대상 목록에 등재 — `docs/dev-log.md` 항목 1

### 🔄 이 제약은 해소 경로에 들어갔다 (2026-08-12, ADR-004)

생성을 **로컬 모델**로 내리고 배포를 **AWS 서울 리전(ap-northeast-2)** 으로
옮기면 `LLM_REGION=kr` 이 문구 교체가 아니라 **실제로 충족**된다. 위의
"외부로 나가는 것은 생성 호출 하나뿐"이 **"외부로 나가는 것이 없다"** 로
바뀐다 — 축소가 아니라 더 강한 참인 주장이다.

배선과 정확성(문법 제약 하 인용·수치 생성)은 확인됐고, **성능·정규화 품질
판정은 AWS GPU 실측 대기 중**이다. 미달 시 폴백은 생성만 API 로 되돌리는
하이브리드이며, 그 경우 이 절의 원래 서술이 그대로 유효하다.

→ 상세는 **ADR-004**. 이 ADR 은 그 판정이 끝날 때까지 **유효하다**
(현재 프로덕션 경로는 여전히 Anthropic 이다).

## 검토한 대안

| 대안 | 기각 사유 |
|---|---|
| 국내 리전 모델(네이버·업스테이지 등) | 키 미확보. 확보하더라도 구조화 출력·프롬프트 캐시·스트리밍 지원 여부를 재검증해야 하고 일정상 불가 |
| opus-5를 1순위로 | 단가 2배($5/$25 vs $3/$15). 골든셋 240문항을 반복 채점하는 개인 참가에서 부담이 크다. 품질 차이가 이 과제(주어진 근거 요약)에서 결정적이지 않다 |
| 프로바이더 2종 병행(planner 원안) | 계정·키·평가를 두 배로 늘리는 비용 대비 이득이 없다. 폴백 목적은 모델 레벨로 충족된다 |

## 비용

sonnet-5 $3/$15 per MTok. **2026-08-31까지 도입가 $2/$10** 적용(현재 해당).
1주 차 dev-log에 실측 단가를 기록해 발표 자료의 운영 비용 근거로 쓴다.

## 되돌리는 방법

`app/llm/base.py` 의 `LLMClient` Protocol 을 구현하면 교체된다. 계층 판정과
출력 검사는 프레임워크 밖 순수 함수이므로 모델 교체의 영향을 받지 않는다.
`.env` 의 `LLM_MODEL` / `LLM_MODEL_FALLBACK` 만 바꾸면 같은 계열 내 교체는 즉시 가능하다.

## 미해결

- **프롬프트 캐시 실측 미완.** 시스템 프롬프트 길이를 문자 수로 추정해
  1,024토큰 하한을 넘긴다고 판단했으나(ko 1,361자 / en 2,157자 / vi 2,080자),
  `count_tokens` 실측은 키 확보 후로 남았다. 미달이면 캐시가
  **에러 없이 조용히 비활성화**되므로 `usage.cache_read_input_tokens > 0` 확인이 필수다.
- **거절 오탐률 미측정.** sonnet-5는 sonnet-4.6보다 사이버 보안 판정이 강화되었고,
  보이스피싱 대응 안내가 정확히 오탐 위험 구간이다. 골든셋에 사기 대응 질의를
  넣어 측정해야 한다.
